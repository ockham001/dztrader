# 帧契约：进度推送

本文件覆盖 `DZ_FRAME_RTN_PROGRESS` 一个帧。总则见《帧契约：通用规则》。

帧使用 `DzExtInstFrameHeader` 扩展头，`instance_id` 标识来源逻辑实例。本帧**同时服务两种级别**（总则 §5）：

- **进程级**：`instance_id` = 进程名（行情网关 `dzmd_ctp` 等）；
- **账户级**：`instance_id` = **账户 ID**（交易网关的账户级登录进度，如 `"00001"`）。**不使用 `网关名:账户ID` 复合键**——网关名是运行期可变的进程实例名，不能作账户身份（[ADR 0056](../adr/0056-td-account-identity-investor-code-and-display-name.md)）。

同一帧类型下两种级别的数据结构完全相同（进度骨架与字段一致），消费方按**帧来源与注册表**区分：`instance_id` 命中账户注册表 = 账户级，否则按进程级处理；两者共用同一份镜像键空间，因此账户 ID 不得等于进程名（契约 td-config §7）。

类型层真相源：`libs/platform/include/dztrader/platform/progress.h`（`ProgressReporter`）。

仅 RTN 推送，无 SET、无持久化、无文件 IO。进程在状态转移 / 进度里程碑时主动推送。

## 数据结构

### ProgressStatus

单条完整推送。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `min` | int | 是 | 进度最小值（通常 0） |
| `max` | int | 是 | 进度最大值；`max <= min`（含 `max==0`）表示不确定进度 |
| `current` | int | 是 | 当前进度 |
| `desc` | string | 否 | 简短文本说明（如 `"订阅合约中"`）；空串/省略 = 无文本 |

**进度语义**：

- `max > min`：确定进度
- `max <= min`（含 `max == 0`）：不确定进度；`current` 值忽略
- `current` 应在 `[min, max]` 范围内；超出时前端钳制到 `[min, max]`（防御性，不报错）；钳制仅适用于确定进度

**消费者约定**：

- `desc` 仅为展示文案，**消费者不得依赖 `desc` 文本做状态判定**（文案调整不得破坏协议语义）
- 需要判定业务状态时使用 `min`/`max`/`current` 数值映射；映射表的真相源由发送方进程维护（实现注释/进程文档），映射变更必须同步所有消费者
- 网关会话类进度（登录/登出状态）：端点语义跨接口类型固定，见下方「网关会话进度骨架」；不得用 `desc` 或具体中间值反推会话状态

JSON 示例：

```json
{"min": 0, "max": 4, "current": 2, "desc": "订阅合约中"}
{"min": 0, "max": 0, "current": 0}
{"min": 0, "max": 10, "current": 10, "desc": "就绪"}
```

## 网关会话进度骨架（跨接口类型约定）

适用于以「登录会话」控制可用性的网关进程（行情源进程、交易接口账户）。各接口类型的阶段划分与 `max` 数值可不同，但**端点语义与建立期推进规则跨接口类型固定**（ADR 0051 / ADR 0059）：

| 位置 | 语义 | 消费者行为 |
|---|---|---|
| `current == min`（`min` 恒为 0） | 未登录：会话不存在 | 唯一允许发起登录的状态 |
| `0 < current < max` | 会话非就绪：建立中 / 重连中 / 失败停在失败阶段 | 不允许登录；允许登出（= 取消/强制中断） |
| `current == max` | 就绪：该接口类型可履行其业务（交易网关 = 可下单可查询；行情网关 = 已登录） | 不允许登录（重新登录须先登出）；允许登出 |

**建立期推进规则**（跨接口类型通用，ADR 0059）：

- **会话建立期的 `current` 单调不减。** 从 `min` 到 `max` 的整条登录链上只前进、不停留在走过的阶段。推荐固定值：`0` = 未登录、`1` = 连接中/重连中、`2` = 已连接；`current > 2` 的阶段（认证、登录、结算确认、初始化等）与 `max` 数值由接口类型定义。
- **失败停在失败阶段。** 链上任一段失败后，`current` 停在该段数值、**不回退**到上一段，`desc` 描述该段失败；该位置仍是中间值（`0 < current < max`），**失败不占端点**——不得用 `min` / `max` 表达失败。失败态只回答「在哪一段失败」，段内具体原因由该接口类型状态帧的 `last_error` 承载，二者在同一次状态转移写出。
- **`current` 回退只表示主动中止。** 只有主动中止（登出 → `min`；前置断线 → 断线段）会使 `current` 回退，语义是「这次会话尝试被打断」。登录链内的失败**不产生回退**，因此消费方不得再把回退当作失败信号。
- **失败不改变端点资格。** 失败态下不可发起登录、可发起登出；恢复统一为「先登出、再登录」（ADR 0051 决策 4），不提供失败态原地重试。
- 账号三态（契约 account-status）把断线重连中归为 Offline，与「会话不可用」一致；但**会话控制**（是否允许登录）只看本骨架的端点，不得用三态反推。
- 前端协议义务：把端点作为会话态的唯一判据（是否允许发起登录 = `current <= min`；是否允许中止 = `current > min`）；登录 pending 的清除**不以 `current` 回退为主信号**——回退只覆盖「主动中止」，失败路径依赖状态帧 `last_error` 的新时间戳（见各接口类型契约的前端义务）；兜底超时保留为最后一道信号。控件形态与按钮 disabled 规则属前端设计（ADR 0051），不进本契约。`desc` 仅展示，不得用于状态判定。

**由各接口类型定义的部分**：阶段划分与 `max` 数值、失败态集合与各失败态的 `current` / `desc`、`last_error` 的字段结构与失败码表——分别由该接口类型的状态契约与连接契约定义（行情网关见《帧契约：行情网关状态》、《帧契约：行情连接与订阅》；交易网关见《帧契约：交易网关状态》、《帧契约：交易账户连接控制》）。本骨架只定跨接口类型通用的端点语义与推进规则，不复述这些数值——同一事实写两处必然漂移。消费方必须按端点相对比较判定，**禁止依赖具体 `max` 或中间值数值**。

## DZ_FRAME_RTN_PROGRESS

**语义**：推送当前进度状态
**数据流**：形态 4（总则 §4.2）——进程或交易账户（帧头 `instance_id` = 来源：进程级为进程名，TD 账户级为账户 ID）→ dzweb；无前端入口；镜像 `progress` 域 → WS 消息 `progress`
**Payload**：JSON（ProgressStatus）

**触发场景**：

1. 进度变化时推送（状态转移、步骤推进、完成、失败等里程碑）
2. `QUERY_FULL_SNAPSHOT` 响应：有活跃进度时推送；无活跃进度时可不推送（总则 §7）

**约束**：

- 单条完整状态：接收方直接覆盖该实例的进度，无需增量合并；后到的覆盖先到的，不累积
- 进程无进度追踪需求时可不实现本帧（不影响其他帧）

**镜像**：
- dzweb 更新该实例镜像的 `progress` 域，并 WS 推送（进程级 key = 进程名；账户级 key = 账户 ID）
- **账户级条目的清理**：网关停止 / 崩溃 / 被移除时，dzweb 按注册表反查该网关账户集，清掉各账户的 `progress` 镜像；注册表降级时放弃清理（宁残留不猜）。账户从配置帧消失时同样清掉。**不得**沿用按进程名清理的旧路径——账户级 key 不含进程名

**前端义务**：
- 以最新推送为准展示；镜像/快照中无 `progress` 域的实例视为无活跃进度
- 超出范围的 `current` 钳制展示，不报错、不反馈
- 账户级进度用于该账户行的登录 / 登出 pending 与连接状态展示，按 `account_id` 精确匹配
