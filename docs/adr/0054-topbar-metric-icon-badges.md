# ADR 0054: 顶栏资源区收敛为三枚「图标 + 数值」徽章（CPU / 内存 / 时钟偏差）

## Status

Accepted（2026-11-23，#452 顶栏资源区重做，最终形态）

Supersedes（**部分**）：[ADR 0048](0048-topbar-resource-badge-layout.md) 的 §1（时钟偏差入口形态：紧凑毫秒 `NTP` 文字徽章）、§3（卷徽章：状态点 + 挂载点短标签）、§4（资源组按可用宽度自适应折叠与 `<lg` 单状态图标）。ADR 0048 §2（卷列表固定顺序）**继续有效**：适用于监控页存储块与其它卷列表消费方，与顶栏无关。服务徽章（MD / TD / STG）继续常驻。

契约同步：《帧契约：系统监控》§2.4（顶栏资源徽章的取景）、§2.9（顶栏时钟偏差徽章口径），**无 payload 变更**。

## Context

监控页五块（#429 拆分）已落地，顶栏资源区仍是 #318 / ADR 0048 的形态：CPU / MEM / `NTP` 文字徽章 + 每个挂载点一枚卷徽章，`≥lg` 按可用宽度自适应折叠、`<lg` 收成单个状态图标。用户 2026-11-23 复盘盯盘体验后，先定「资源区只留 CPU / 内存 + 右上墙钟」，随后在预览中进一步拍板**最终形态**：

1. **顶栏不需要日期时间**。32px 常驻条上「现在几点」不是盯盘要看的信号（交易时间由行情 / 持仓表达），而显示墙钟就要每秒重渲染一次顶栏子树——成本真实、收益为零。日期 / 星期 / 时区 / 四档降级全都是为墙钟服务的复杂度，随墙钟一起删除。
2. **顶栏不需要 `NTP` 这个文字标签**。`NTP` 是协议名而不是用户概念；用户看到的应是「本机时钟偏了多少」，而不是「NTP 那家伙怎么样」。时钟偏差本身仍是值得扫读的信号（本机墙钟系统性偏移会影响所有时间的判读），只是不再以文字徽章 + 墙钟两处呈现。
3. **32px 状态条上，文字标签是稀缺宽度**。CPU / 内存两枚文字徽章（`CPU` / `MEM` + 数值）已经在窄屏占掉可观宽度，再放一枚 `NTP` 文字徽章与右侧控件就会互相挤；而 CPU / 内存 / 时钟偏差三者的**图标**在既有内置图标集里都有语义明确、风格一致的现成资源（CPU、memory-module；时钟偏差用既有 clock_time 简单表盘）。
4. **卷徽章是误报噪音的最大来源**。卷数量随机器变化（3 卷 → 6 卷），顶栏会被卷占满；卷警告与交易 / 策略 / 行情告警并列在同一常驻条里，扫读时无法一眼区分「哪一类问题」。用户明确否决「只在异常时才出现的卷 chip」——条件出现的元素本身会变成需要解读的信号，且每次推送都在出现 / 消失之间抖动。
5. **自适应折叠与 `<lg` 单状态图标让同一份信息按宽度出现 / 消失**。这套机制是为「卷数量不定」服务的；卷徽章删除后资源项固定为三枚，折叠机制失去存在理由。

## Decision

**1. 资源区只保留三枚「图标 + 数值」徽章，顺序 CPU → 内存 → 时钟偏差，任何宽度都常驻。** 位置在服务徽章（MD / TD / STG）与分隔线之后、左侧；右侧只留连接状态 + 主题 / 设置。删除全部卷徽章（挂载点、状态点、短标签、溢出列表里的卷项）与独立文字 `NTP` 徽章；不再有按可用宽度自适应折叠、`▾ N` 浮层、`<lg` 单状态图标；**不显示日期 / 时间，也不再每秒 tick**。`topbarOverflow` 模块、墙钟组件与墙钟专用导出全部删除。

**2. 三枚徽章的形态与语义**：

- **CPU**：内置 `CPU` 图标（12px）+ 整数百分比（`19%`）；**内存**：内置 `memory-module` 图标 + 整数百分比（`50%`）。两者沿用既有 70% / 90% 定档：normal 成功绿 / warn 黄 / danger 红（用户 2026-11-23 拍板「19% / 50% / +23ms 正常要绿色、高了警告」），不可用时数值显示「不可用」+ 中性色（title 给原因，不得用 0 冒充）。
- **时钟偏差**：使用既有 `clock_time` 简单表盘图标（用户拍板「就一个时钟」；12px 下不引入环形箭头等复杂细节）+ 紧凑带符号整数毫秒（`+23ms`）。偏差正常时数值成功绿，`|offset|` 超 `clock.offset_warn_ms` 只让**数值文本**变黄、超 `offset_error_ms` 只变红；快照未到达 / 尚未探测 / 本轮全部失败显示 `—`（不得用 0 冒充）；`clock = null`（配置关闭）整枚徽章不渲染。
- **图标永远中性色且 `aria-hidden`**（Icon 组件自带），状态只由数值文本的颜色表达；三枚徽章的数值都带单位、`tabular-nums`，推送刷新时不左右跳位。

**3. 每枚徽章都有完整可访问名与悬停说明。** 整枚徽章是 `role="img"` + `aria-label`（如「CPU 使用率 19%」「时钟偏差 +23ms，正常」），图标与数值文本都不单独承担语义；`title` 给完整名称 + 读数 + 含义（时钟偏差另含误差界、来源、stratum、上次探测相对时间与「测量质量」提示；不可用时给原因）。偏差档位词（正常 / 偏大 / 过大）同时进 `aria-label`，颜色只是冗余信号（WCAG 1.4.1）。

**4. 口径复用，不新造第二套。** 偏差定档继续走 `sysmonClock.clockOffsetLevel`（内部 `useResourceLevel.thresholdLevel`）+ `resolveClockThresholds`（配置镜像缺失回退契约默认 100 / 1000 / 200ms）；相对时间继续用 `formatAge`；徽章模型抽成纯函数 `composables/topbarNtp.ntpBadgeModel`（组件只做渲染，与 `topbarNtp.spec.ts` 单测一一对应）。

**为什么不用另外七种方案**：

- **(A) 保留文字标签（`CPU` / `MEM` / `NTP` + 数值）**：否决。32px 条上文字标签把每枚徽章宽度翻倍，且窄屏下三枚 + 服务徽章 + 右侧控件必然互相挤；图标 + 数值已能扫读，完整名称在 `aria-label` / `title` 里。
- **(B) 给时钟偏差用现有纯表盘图标（`clock_time` / `time`）**：否决。纯表盘 = 「当前时间」，与「本机时钟偏了多少」是两件事，会被读成顶栏又显示了时间；必须用「表盘 + 环形箭头」这种同步语义的组合图标。
- **(C) 保留独立文字 `NTP` 徽章 + 另放墙钟**：否决。墙钟已删除；而且两个入口表达同一份 `clock` 域，把偏差并入资源区一枚图标徽章是最短路径。
- **(D) 保留墙钟（日期 / 星期 / 时区 / 秒级 tick / visibility 暂停）**：否决。顶栏不需要日期时间；秒级定时器与四档降级只为墙钟存在，删除后顶栏无定时器、无 visibility 逻辑。
- **(E) 条件卷警告 chip（只在某卷异常时出现）**：否决。用户明确否决；条件出现意味着「出现 / 不出现」本身要解读，每 5 秒推送一次时 chip 会在异常 / 恢复之间反复闪现，制造新的抖动。卷容量与空量告警归监控页存储块。
- **(F) 保留卷徽章但只在宽屏显示**：否决。同一条信息在不同宽度下出现 / 消失，扫读位置不稳定；资源项已固定为三枚，顶栏没有宽度压力，没有折叠的必要。
- **(G) 偏差超阈值时整行（图标 + 数值）变色 / 图标也变色**：否决。DESIGN「The One Job Rule」：图标是「这是什么指标」的标识，不承担状态语义；只有数值文本着色才能让「哪个指标、偏了多少」在同一眼读清。

## Alternatives

见上（七个「为什么不用」已覆盖候选）。补充两条被否决的次要选项：

- **图标用内联 SVG 而不是内置图标资源**：否决。仓库已有 650+ 内置图标、`Icon` 组件按名取 `/icons/builtin/<name>.svg` 并用 mask + `currentColor` 渲染，`iconNames.spec` 还会机器校验图标名存在；内联 SVG 等于在顶栏再开一套图标来源。
- **三枚徽章继续用文字标签的 `TopbarResourceBadge` 形态、只把 NTP 换成图标**：否决。三枚徽章视觉语言必须一致（同一行里两枚文字标签 + 一枚图标会显得 NTP 是「附件」），统一为图标 + 数值。

## Consequences

- **顶栏行为在任意宽度一致**：三枚常驻图标徽章 + 服务徽章 + 右侧连接状态 / 主题；没有折叠、没有浮层、没有 JS 宽窄行为分支，也没有定时器。390 宽最坏情况（CPU/MEM 三位数百分比、偏差 `-1000ms`）实测不溢出、三枚徽章整枚可见（窄屏只由 CSS 收紧 topbar 内边距与资源区间距）。
- **资源误报噪音下降**：卷警告从顶栏彻底移除（有意取舍，不是能力缺失）；CPU / 内存的黄 / 红仍是顶栏保留的资源告警；时钟偏差过大时只有数值变黄 / 变红。
- **语言中立**：`CPU` / `MEM` / `NTP` 三个英文缩写文字标签全部消失，图标 + 数值不依赖语言；`NTP` 这个协议名不再出现在界面上。
- **删除面**：`components/layout/TopbarClock.vue` 与 `composables/topbarClock.ts`（墙钟四档文本 / 时区 / title 拼装，**只在本票中间形态出现过，最终未保留**）；偏差徽章模型由 `composables/topbarNtp.ts` 承担；`TopbarResourceBadge.vue` 被 `TopbarMetricBadge.vue`（图标 + 数值）取代；`layout.css` 移除 `.topbar-clock*` 与墙钟四档媒体规则、移除 `.res-dot` / gauge / overflow / measure / 旧 datetime / `.topbar__ntp` 规则。
- **保留面**：`sysmonClock.clockOffsetLevel` / `clockDomainState` / `clockFailureSummary` / `clockProbeAgeSec` / `resolveClockThresholds` 等继续供监控页时钟块与顶栏徽章共用；`formatCompactSignedMilliseconds` 继续服务顶栏偏差数值（整数毫秒）。
- **契约无 payload 变更**：§2.4 / §2.9 只改「顶栏如何展示」的措辞；快照 / 配置 / REST / WS / `generated.ts` 全部不动，dzweb 领域服务不需要动。
- **文档同步**：README「资源监控」段、`docs/components/dzsysmon.md`、本 ADR；ADR 0048 顶部加 Superseded-in-part 引用（不改其 Decision 正文）。
- **测试口径**：`Topbar.spec.ts` 重写（三枚图标徽章渲染 / 图标名 / 数值与档位 / `—` / 配置关闭不渲染 / title 与 aria / 无墙钟与秒级定时器 / 无媒体规则隐藏徽章 / 390 样式不变量）；新增 `topbarNtp.spec.ts` 纯函数单测；卷色标一致性用例此前已改为 CPU / 内存一致性（`ResourceLevelConsistency.spec.ts`）。四档墙钟 / 每秒 tick / visibility 用例随墙钟删除。
- **风险**：12px 图标加 10px 数值的视觉密度需要真实浏览器验收（已用静态夹具在 390 / 768 / 1024 / 1440 实测不溢出）；图标名大小写敏感（`iconNames.spec` 机器校验 `CPU` / `memory-module` / `clock_time` 三个文件都存在）。
