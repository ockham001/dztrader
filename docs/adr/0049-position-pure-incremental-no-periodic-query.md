## Context

持仓此前按 ADR 0008 的**混合模型**实现：聚合查询建权威基准，成交 / 委托回报做盘中增量，另以 Ready 后每 `qry_position_interval_s`（默认 60s）的周期查询做「漂移自愈」。周期查询承担了三件事：纠正增量累积误差、覆盖其他终端在非本会话下的交易、以及作为增量路径出错时的唯一兜底。

要求回到**纯增量**，并且承载两类新业务（期权、交易所套利合约）。查证后的事实改变了这个设计的前提：

- **CTP 没有任何持仓 / 资金的主动推送回调**（`OnRtn*` 全表无此项）。持仓的唯一权威入口就是 `ReqQryInvestorPosition`，因此"登录后的基准查询"不是可删的遗留，是结构性必需。
- **若干持仓变化根本不产生成交回报**，且全部发生在**盘后**：期权行权配对、卖方履约、到期作废 / 自动行权、以及交易所的**盘后自动组合**（客户未申请也会生成组合持仓行）。它们在盘中零回调，只能由"下一次登录的基准查询"吸收。旧版 20230813 正是靠"每日重新登录"覆盖这一类（其进程内从不做周期查询）。
- **私有流是投资者级而非会话级**：同账号其他终端（快期 / 手机 / 其他软件）下的单，本会话同样收到 `OnRtnOrder` / `OnRtnTrade`。旧版与新代码都据此把无本地映射的回报标成外部单（`/external`）后走同一条持仓路径。证据是强暗示而非明文（头文件的 RESTART 边界只有时间没有会话；上期技术文档教客户端用 `FrontID+SessionID` 过滤出自己的回报——只有混着别人才需要过滤），但两个独立实现都建立在这个假设上并长期实盘可用。
- 现状代码存在一处**被周期查询掩盖的今昨计算错误**：`yd_volume = YdPosition`、`today_volume = Position - YdPosition`。CTP 的 `YdPosition` 是**静态值**（交易日开始时的昨仓，平昨后不减少），真实昨仓 = `Position - TodayPosition`。周期查询的反复覆盖加 `[0, volume]` 夹取掩盖了这个偏差；一旦取消轮询，偏差将永久保留。

## Decision

1. **取消周期查询**：删 `qry_position_interval_s`（配置项 / 契约字段 / 前端类型与 schema）、`schedule_position_poll`、`on_position_poll_timer`、`set_position_poll_interval`。持仓不再有任何定时重查。
2. **唯一权威初始值 = 登录基准查询**。「重连」即「重新登录」，同属初始值语义，重连后照常发起一次基准查询（不是轮询，重连本身罕见）。
3. **基准查询失败 = 登录失败**：重试 3 次、间隔 3 秒；仍失败则停在当前进度、**不转 Ready**、推 ERROR 通知，由用户处理。删 `schedule_data_resync` 与 `resync_retry` 两条重试链。**「查不到」不是失败**：`is_last` 正常到达但零行 = 成功（空账户合法）。
4. **今昨口径修正**：`today = TodayPosition`、`yd = Position - TodayPosition`，对全部交易所成立（非 SHFE 单行满足；SHFE/INE 的今仓行为 `today=Position, yd=0`、昨仓行为 `today=0, yd=Position`）。
5. **会话不得跨交易日**：运行期检测到回报的 `TradingDay` 与当前交易日不一致，记 ERROR 并主动登出。不加配置层校验（连续在线配置本身合法）。
6. **套利 / 组合合约**：`product_class == DZ_PRODUCT_SPREAD` 的持仓行跳过（不推帧、不落库、DEBUG 日志），成交回报照常记录但同样不参与持仓统计；单腿合约是普通期货合约，照常增量维护。不支持行权 / 自对冲 / 组合动作指令。
7. **期权**：记账 + 普通报单（买卖开平走既有 `OnRtnTrade` 路径），不支持发起行权 / 自对冲。盘后减仓由次日登录基准吸收。
8. **外部单与自营单同权**：共用同一条持仓路径，无 `FrontID/SessionID` 过滤；套保仓（`HedgeFlag != 投机`）全部计入，不静默丢弃。

**为什么不再保留周期查询**：它是本 ADR 要拿掉的东西本身。其三项职责中，(a) 纠偏由基准查询 + 会话不跨日覆盖（盘后变化全部落在次日登录）；(b) 其他终端交易由投资者级私有流实时覆盖；(c) "增量出错"的兜底在数学上不是兜底——真正能纠错的只有重新查询，而周期查询只是在"错误持续时间内卖出一个固定延迟"。代价是**失去自愈**：一旦增量真出错（bug、私有流缺口、未覆盖来源），账面偏差将持续到下次登录。这是有意识的取舍，用"出错可观测"（见 Consequences）换掉"固定 60s 一次的全量查询"。

## Consequences

**正面**：持仓变化从"最多滞后一个查询间隔"变为实时；一天的全量查询次数从约 1440 次降到个位数（每日登录 + 重连），显著降低柜台查询流控压力；语义单一——持仓只有"基准 + 增量"两条路径，不再有"周期查询覆盖增量"这种难推理的交错。

**负面 / 已知限制**：

- **失去自愈**：增量累积误差、私有流缺口、未覆盖的持仓来源都会持续到下次登录。代码侧需保留可观测性（跳过项记日志、未知枚举计数与通知）。
- **非 SHFE 交易所的 generic 平仓今昨归属是本地约定**（先今后昨溢出）。成交回报的 `OffsetFlag` 只有"平仓"，不告知从今仓还是昨仓扣除，交易所内部顺序无法由回报自证。只影响今昨显示与手续费归类，不影响总量与可平量。
- **私有流投资者级是未验证假设**：无一手明文。若某柜台实际按会话推送，外部单将只在登录重放中出现。需留运行期告警。
- **期权行权 / 履约 / 到期零回调**，正确性依赖"次日登录基准"。同理，盘后自动组合持仓会凭空出现。两者都使"会话不跨交易日"成为**正确性前提**而非优化。
- **资金仍无周期查询**（ADR 0045 决策 6 保留），盘中资金停在最近一次查询。

**契约影响**：《帧契约：TD 数据同步》§3 持仓写端由「混合模型」改为「纯增量」、§4 查询链路改为「失败即登录失败，无定时补查」、§7 边界表改写 3 行（旧会话残留写入 / 其他终端交易 / 资金盘中不刷新）、删除 1 行（查询在途窗口成交）、新增 4 行（无自愈 / 非 SHFE 今昨归属 / 期权与盘后自动组合 / 套利组合不统计）；《帧契约：交易网关配置》删 `qry_position_interval_s`（`SetQryIntervals` op 保留另外两个字段）；`GLOSSARY`「收敛窗」废止、新增「持仓基准」；`docs/components/dztd_ctp.md` 与 `dzweb.md` 同步。**代码侧删除见 #412 / #413**——本 ADR 只改契约，契约先于实现是仓库明文要求（`general.md` §11.3）。
