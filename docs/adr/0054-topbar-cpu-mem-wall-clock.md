# ADR 0054: 顶栏取景收敛为 CPU / 内存常驻 + 右上墙钟（含时钟偏差括号）

## Status

Accepted（2026-11-23，#452 顶栏资源区重做）

Supersedes（**部分**）：[ADR 0048](0048-topbar-resource-badge-layout.md) 的 §1（时钟偏差入口形态：紧凑毫秒 `NTP` 徽章）、§3（卷徽章：状态点 + 挂载点短标签）、§4（资源组按可用宽度自适应折叠与 `<lg` 单状态图标）。ADR 0048 §2（卷列表固定顺序）**继续有效**：适用于监控页存储块与其它卷列表消费方，与顶栏无关。服务徽章（MD / TD / STG）继续常驻。

契约同步：《帧契约：系统监控》§2.4（顶栏资源徽章的取景）、§2.9（顶栏墙钟与偏差括号口径），**无 payload 变更**。

## Context

监控页五块（#429 拆分，主机条 / CPU / 内存 / 存储 / 网络 / 时钟）已按参考应用布局落地，顶栏资源区仍是 #318 / ADR 0048 的形态：CPU / MEM / `NTP` 徽章 + 每个挂载点一枚卷徽章，`≥lg` 按可用宽度自适应折叠、`<lg` 收成单个状态图标。用户 2026-11-23 复盘盯盘体验后认为这套取景有三个问题：

1. **卷徽章是误报噪音的最大来源，且与「资源类只写日志」的决策相冲突。** 卷数量随机器变化（3 卷 → 6 卷），顶栏被卷占满；卷警告与交易 / 策略 / 行情告警并列在同一个常驻条里，扫读时无法一眼区分「哪一类问题」。用户明确否决了「只在异常时才出现的卷 chip」——条件出现的元素本身会变成一个需要解读的信号（「它出现是出事了，还是刚刷新？」），还带来布局抖动。
2. **一枚只给数字的 `NTP` 徽章信息密度低、位置不对。** 时钟偏差是「本机墙钟准不准」，它天然依附于「现在几点」这个读数；单独放一枚 `NTP` 徽章后，用户要先找到徽章再在心里把数字和当前时间对齐。而顶栏右上角恰恰是人看时间的位置，那里此前是空的。
3. **自适应折叠 + `<lg` 单状态图标让同一份信息在不同宽度下出现 / 消失。** 收进 `▾ N` 的事实等于默认不可见；窄屏收成一个图标后，CPU / 内存读数完全消失。这套机制是为「卷数量不定」服务的；卷徽章删除后资源项固定为两枚，折叠机制失去存在理由（`composables/topbarOverflow` 变成死模块）。

## Decision

**1. 资源区只保留 CPU / 内存两枚徽章，任何宽度都常驻。** 删除全部卷徽章（挂载点、状态点、短标签、溢出列表里的卷项）与独立 `NTP` 徽章；不再有按可用宽度自适应折叠、`▾ N` 浮层、`<lg` 单状态图标。`topbarOverflow` 模块与其测试删除。CPU / 内存保留 70% / 90% 两档状态色（normal 绿 / warn 黄 / danger 红）、整数百分比与既有 title；宽度紧时由 CSS 断点收紧资源区间距（仍常驻），不折行、不横向溢出。

**2. 右上新增墙钟组件 `TopbarClock`，偏差作为墙钟的括号。** 本机 `Date`、24 小时制、本地时区、每秒 tick；页面 `document.hidden` 时暂停，恢复后立即对齐当前时刻（不补播隐藏期间的秒）。四档格式（断点 1280 / 1024 / 768，**秒永远保留**）：`2026-01-02 周四 13:25:36 (+23ms)` → `01-02 周四 13:25:36 (+23ms)` → `周四 13:25:36 (+23ms)` → `13:25:36 (+23ms)`；四段文本恒在 DOM，可见性由纯 CSS 断点切换（JS 不读视口宽度、不用容器查询）。偏差括号 `(+23ms)`（紧凑整数毫秒，正 = 本地快）平时中性色；`|offset|` 超 `clock.offset_warn_ms` **只有括号内文本**变黄（`--status-warning-on-surface`），超 `offset_error_ms` 只变红（`--status-error-on-surface`），整块时钟不变色。未探测 / 本轮全部失败显示 `(—)`（不显示 0）；`clock = null`（配置关闭）不渲染括号。`<time>` 带 `aria-label`（完整日期星期时间 + 偏差状态）与 title（时区、1 位小数带符号偏差、误差界、来源、stratum、上次探测相对时间；不可用时给原因）。

**3. 时钟放在顶栏最右侧**：连接状态槽在其左侧，主题按钮保持原有相对顺序。

**4. 口径复用，不新造第二套。** 偏差定档继续走 `sysmonClock.clockOffsetLevel`（内部 `useResourceLevel.thresholdLevel`）+ `resolveClockThresholds`（配置镜像缺失回退契约默认 100 / 1000 / 200ms）；相对时间继续用 `formatAge`；四档文本 / 括号 / title / aria 的拼装抽成纯函数 `composables/topbarClock.ts`（组件只做 tick 与渲染，与 `topbarClock.spec.ts` 单测一一对应）。

**为什么不用另外五种方案**：

- **(A) 条件卷警告 chip（只在某卷异常时出现）**：否决。用户明确否决；条件出现意味着「出现 / 不出现」本身要解读，且每 5 秒推送一次时 chip 会在异常 / 恢复之间反复闪现，制造新的抖动。卷容量与空量告警归监控页存储块。
- **(B) 保留卷徽章、只在宽屏显示**：否决。同一条信息在不同宽度下出现 / 消失，扫读位置不稳定；而且资源项已固定为两项，顶栏没有宽度压力，没有折叠的必要。
- **(C) 独立 `NTP` 徽章与墙钟并存**：否决。等于两个时钟入口：墙钟在右上、偏差在左侧资源区，中间隔着服务徽章；同一份 `clock` 域在监控页已有完整卡片。把偏差并入墙钟的括号，让「现在几点 / 准不准」在同一眼完成。
- **(D) 墙钟取快照 `timestamp`**：否决。那是数据龄口径（停推时快照时间会冻住），墙钟必须取本机 `Date`，否则页面断连时用户会看到一个停止的时钟并误以为系统时间停了。
- **(E) 偏差超阈值时整块时钟变色**：否决。DESIGN「The One Job Rule」：整块变色会让时钟本身变成告警体、时间读数可读性下降；只对括号着色即可扫读，且 `-on-surface` 配对档保证黄色 / 红色文本在顶栏底色上的对比度。

## Alternatives

见上（五个「为什么不用」已覆盖候选）。补充两条被否决的次要选项：

- **四档格式用 JS 读断点 / 容器查询**：否决。格式只是「同一组文本片段显示哪几段」，CSS 能表达就不该引入行为分支；既有断点白名单（768 / 1024 / 1280）由测试机器强制，容器查询会绕过这条门禁。
- **偏差括号自己计时 / 复用监控页的 1 秒 ticker**：否决。顶栏是全站常驻组件，不能依赖某个页面挂载；墙钟自带定时器并在卸载时清理，页面隐藏时暂停，避免后台标签每秒重渲染。

## Consequences

- **顶栏行为在任意宽度一致**：只剩两枚常驻资源徽章 + 右上墙钟；没有折叠、没有浮层、没有 JS 宽窄行为分支，扫读位置固定。
- **资源误报噪音下降**：卷警告从顶栏彻底移除（这是有意的取舍，不是能力缺失）；CPU / 内存的黄 / 红仍是顶栏唯一保留的资源告警。NTP 偏差过大时只有括号变黄 / 变红，不整块报红。
- **时刻与准度同眼可读**：墙钟回答「现在几点」，括号回答「本机时钟准不准」；完整明细（每台服务器、同步服务检测）仍在监控页时钟块。
- **删除面**：`composables/topbarOverflow.ts` + `__tests__/topbarOverflow.spec.ts`；`sysmonClock.clockBadge` / `clockBadge` 类型 / `CLOCK_BADGE_LABEL`（`clockOffsetLevel`、`clockDomainState`、`clockFailureSummary` 等继续供监控页与墙钟使用）；`TopbarResourceBadge` 收敛为 cpu / mem 两种形态（删掉 `disk` 形态与 `mount` / `testId` props）；`layout.css` 移除 gauge / overflow / measure / NTP / 旧 datetime 规则。
- **契约无 payload 变更**：§2.4 / §2.9 只改「顶栏如何展示」的措辞；快照 / 配置 / REST / WS / `generated.ts` 全部不动，dzweb 领域服务不需要动。
- **文档同步**：README「资源监控」段、`docs/components/dzsysmon.md`、本 ADR；ADR 0048 顶部加 Superseded-in-part 引用（不改其 Decision 正文）。
- **测试口径**：`Topbar.spec.ts` 重写（CPU / 内存常驻四档宽度断言、无卷 / NTP / overflow 回归、四档 DOM 片段、偏差三档只作用于括号、`(—)` 与配置关闭、tooltip 字段、tick / visibility / 卸载）；新增 `topbarClock.spec.ts` 纯函数单测；卷色标一致性用例改为 CPU / 内存一致性（`ResourceLevelConsistency.spec.ts`）。
- **风险**：四档可见性由 CSS 断点决定而 jsdom 无布局，因此用 layout.css 源码断言补位（与 MonitorViewTrend.spec 的响应式断言同一写法）；390 宽下资源区间距收紧到 `--spacer-6`，保证 CPU / 内存三位数百分比 + 最长偏差括号仍整枚可见（已用真实浏览器实测）。
