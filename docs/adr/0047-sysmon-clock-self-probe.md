# ADR 0047: dzsysmon 时钟偏差监控——自测而非读守护进程状态，只读不校时

## Status

Accepted（2026-11-06，#294 契约与 ADR 先行）

Supersedes（**部分修订**，仅这一句）：[ADR 0034](0034-sysmon-resource-thresholds-log-only.md) 决策 1 末句「`dzsysmon` 的 `NOTIFY_UI` 只保留真故障（历史库不可用、配置下发失败）」的边界——**时钟偏差的 error 档**是第三个弹窗来源；warn 档与同步服务检测仍不弹窗。ADR 0034 的其余决策（含「资源类阈值判定不再产生 UI 通知」本身）全部保留。

契约同步：《帧契约：系统监控》§1 / §1.1 / §2 / §2.5 / §2.6 / §2.7 / §2.8 / §2.9 / §3.1 / §3.1.1 / §4 / §5 / §6 / §7 / §8；《帧契约：REST》§2.8；术语见 `GLOSSARY.md`（时钟偏差 / 时钟误差界 / 时间同步服务）。

## Context

策略的定时调度（`dz_schedule_at` / `dz_schedule_daily` 按本地时刻换算）、交易小节与竞价窗口判断、日志与交易记录的时序对照都按本地墙钟换算。本地墙钟一旦偏离真实 UTC，这些判断会**系统性偏移且静默**——当前系统对此完全不可观测：

1. `dzsysmon` 明确不采集 NTP 时间偏移；全仓没有任何时钟偏差指标、判定或通知。
2. 唯一相关机制是历史库的 `clock_jump` 标记：只在跳变超过 5 秒时记录，且只在 `history.enabled=true` 时运行。它回答「刚才跳过没有」，不回答「现在偏多少」。
3. 前端顶栏曾有的 NTP 徽章是写死的假数字，已删除并有测试断言不得回归。
4. 本机可能根本没开时间同步服务（Windows 10/11 上 W32Time 未启用是常见状态；Linux 上可能同时装多种服务，也可能一个都没起），**没有人会主动去查**。

使用者需要的不是「时钟很准」这个结论，而是：偏差多大、这个数字可不可信、有没有人在管、要不要现在处理。

2026-11-04 在本机（Ubuntu / chrony 已运行）做了自测与 chrony 自报值对照，证明自测精度足以支撑 100 ms 判据：四台服务器（其中三台国内）各 8–10 次采样，中位偏差与 chrony 自报值相差 **1.5–4 ms**（相对 100 ms 判据有 25–60 倍余量）；误差上界（½·RTT + root dispersion）实测 **p50 = 52 ms、max = 71 ms**，`bound_alarm_ms = 200` 取约 4 倍余量。同时 8 台候选服务器中有 4 台全部超时——这既是「必须多服务器 + 单台失败不影响整体」的证据，也是测试必须注入假传输的原因。

## Decision

### 1. 自测为主，不读任何守护进程状态

进程自己按 NTPv4 客户端模式（RFC 5905 的简化子集，mode 3 请求 / mode 4 响应，48 字节报文，UDP/123）向配置的服务器列表探测，算出本地墙钟相对参考源的有符号偏差与误差上界。同步服务检测只作**辅助**：枚举运行中的服务名（Linux 扫进程表精确匹配 `chronyd` / `ntpd` / `systemd-timesyncd`；Windows 查 `W32Time` 服务状态），不解析其内部状态、不判故障、不弹窗。

**为什么不用另外三种方案**：

- **(A) 读 chrony 命令 socket / 解析 `chronyc tracking`**：守护进程没开时就没有答案——而「守护进程没开」恰恰是要监控的场景之一；实测 `/run/chrony` 为 `drwx------ nobody:nogroup`，普通用户不可读（`chronyc` 需回落 `127.0.0.1:323` 才成功），读它要么加组要么提权，引入部署约束；且只覆盖 chrony 一种实现。
- **(B) exec `timedatectl` / `ntpq` / `systemctl` / `w32tm` 并解析文本**：启动外部进程 + 解析本地化文本，随发行版、语言、版本漂移；Windows `w32tm` 的输出受显示语言与 OEM 代码页影响，解析是已知脆弱面。
- **(C) 直接调平台 API 读系统同步状态**（Linux `adjtimex`、Windows W32Time 服务状态）：只能回答「内核 / 服务**认为**是否已同步」，不能回答「偏多少、误差多大」；`STA_UNSYNC` 是布尔，W32Time 服务在运行也不等于时钟准。它适合作为辅助判据（本 ADR 用它填快照的 `kernel_synced`），不能替代偏差测量。

自测是**单一代码路径**跨平台，且在守护进程未开启时仍给出答案。

### 2. 只读不校时

不调用任何校时接口、不做提权助手。同步始终交给 chrony / systemd-timesyncd / W32Time；本功能只报告。

**为什么不用另外三种方案**：

- **(A) 程序内自动步进校时**：需要 root / admin，必须引入提权助手，扩大部署约束与安全面；程序自动跳时钟会让策略里所有壁钟判断瞬间跳变，比偏差本身更危险。
- **(B) 调用平台校时命令**（`chronyc makestep`、`w32tm /resync`）：同样需要管理员权限，且依赖特定守护进程存在；与 (A) 一样把「监控」变成了「会改变系统状态的写入方」，还会与正在缓慢调整的守护进程互相拉扯。
- **(C) 提供「一键校时」按钮**：看似只是触发 (B)，实际把权限提升、错误处理与「谁有权改系统时钟」全部带进 WebUI，收益只是省掉一次管理员操作——监控职责被稀释。

校时是管理员决策，不是监控程序的职责。

### 3. 部分修订 ADR 0034 的静默原则

偏差的 **error 档**（|偏差| ≥ `offset_error_ms`，默认 1000 ms）保留 `NOTIFY_UI`（`popup=true`）；**warn 档**（默认 100 ms）**与同步服务检测仍只写日志 + 卡片色标 / 提示，不弹窗**。误差界（`bound_ms`）越界（默认 `bound_alarm_ms = 200`）只写日志 + 卡片内「测量质量」提示，不参与偏差判定、不弹窗。

**为什么不用另外三种方案**：

- **(A) 完全沿用 ADR 0034 的静默（error 档也不弹窗）**：偏差 ≥ 1 秒会让策略里**所有**壁钟判断系统性偏移，且偏移是静默的；它不属于「资源占用高是常态」那一类，而是「现在所有时间判断都错了」的故障，必须让人立刻决策。
- **(B) warn 档也弹窗**：100 ms 量级的偏差在网络正常时也会偶发（自测精度本身是 1.5–4 ms，但聚合样本受网络抖动影响），把它升为打断通道会稀释弹窗语义——与 ADR 0034 否决资源类弹窗的理由相同。
- **(C) 用 toast 代替 popup**：ADR 0034 已否决 toast（它仍是主动推送，盯盘时同样干扰专注）；本 ADR 不重新引入。

边界只有 error 档：**不新增通知帧**，复用既有 `NOTIFY_UI`；同步服务检测与误差界质量提示永远不弹窗。

### 4. 不进历史库

只保留最近一轮结果 + 每次探测一条日志；不新增 `sysmon.db` 列、不动 `kSchemaVersion`、不做趋势图。

**为什么不用另外三种方案**：

- **(A) 新增标量列存偏差**：`libs/sysmonstore` 只有 `CREATE TABLE IF NOT EXISTS`，没有任何 `ALTER TABLE` 迁移路径；新增标量列必须升 `kSchemaVersion` 并写迁移代码，否则旧库在 prepare 阶段失败。
- **(B) 塞进现有 60 秒 min/max/avg/last 桶模型**：探测是**事件**而非周期采样（默认一天 5 次），桶里几乎全是空值，趋势图只有断点；且桶模型无法表达「这一轮测了几台、哪台失败」。
- **(C) 单独建探测历史表**：为低频事件新增一套 schema / 保留 / 查询链路，成本远大于收益；事后分析靠日志已足够回答「昨晚某时刻准不准」。

## Consequences

- **`dzsysmon` 增加一个探测定时器**：按 `probe_times` 的墙钟时刻排程（单调时钟定时器排到下一个墙钟时刻、每次重算；错过跳过不补采；不区分周末与节假日；进程启动后立即探测一次），与既有计量 / 推送定时器并列；探测走 Asio 异步 UDP，不阻塞采集与帧处理。事件驱动边界不变（[ADR 0023](0023-sysmon-in-process-periodic-sampling.md) 的进程内周期采样例外仍只授予 `dzsysmon`）。
- **契约**：《帧契约：系统监控》新增 `DZ_FRAME_QUERY_SYSMON_CLOCK`（形态 3、无 RTN）、快照 `clock` 域（§2.9）、可用性键 13→15（§2.5）、时间偏差计算语义（§2.7）、时间判定对象（§2.8）、`clock` 配置段（§3.1）、快照触发场景（§4）；《帧契约：REST》§2.8 新增 `POST /api/sysmon/clock/probe`。手动查询复用既有快照推送——不新增 RTN 帧、镜像域或 WS 消息名。
- **弹窗通道**：`NOTIFY_UI` 的弹窗来源增加「时钟偏差 error 档」；ADR 0034 的「弹窗 = 需要我立刻做点什么」语义仍然成立（时钟偏 1 秒确实需要立刻处理）。
- **顶栏不加时钟徽章**：既有「无 NTP 徽章」断言保持有效；信息在监控页时间卡片。
- **已知限制**：容器内看不到宿主同步服务（`daemons` 为空数组，以自测结果为准）；自测精度受网络影响，误差界随网络质量变化（误差界超阈值只提示「测量质量」，不判偏差）；不做 PTP / 硬件时间戳、不做时区 / DST 校验、不区分交易日历；服务器返回 KoD 时退避 / 拉黑，不持续重试；不检测非主流同步服务。
- **不写时钟**：本功能与 OS 同步服务无竞争。
