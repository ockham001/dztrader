# ADR 0052: 资源监控页改按参考应用布局分块重做（取代「主机条 + CPU 宽卡 + 指标台账」方向）

## Status

Accepted（2026-11-22，#429 / #430）

被取代的是 2026-11-18 #360 拍板的版面方向（其实现 #361 / #362 / #363 / #370 已合并）。旧方向不是 ADR，
因此本 ADR 是新增而非 Supersedes；#360 已在 2026-11-22 关闭为 not planned。

## Context

- #360 当时的论证是「六张等权卡片在结构上禁止『最紧的那一项』浮出来」，于是改成「主机条 + CPU 宽卡 + 指标台账」，
  并拒绝卡片化的类目默认排列。
- 用户 2026-11-22 复核后认为：实际页面与最初的设计参照（系统「资源」应用的版面）不一致——参照是
  「一条通栏主机信息条 + 按子系统分块」，而台账是「一张连续表」，两者是不同的信息架构；同时台账方向
  产生的若干局部问题（#373–#378）仍在等拍板。用户明确决定不再受 #360 / #370 的版面决议约束。
- 本次参照（已 pin）：① 系统「资源」应用（`net.nokyan.Resources`）的版面；② 本机主机面板插件
  （`@local/dsh-host-panel`）的主机条行为——整条允许换行、单条内容不换行、标签 / 值分色、状态槽恒在所在行最右。
- 约束：不改帧契约、`generated.ts`、store 净化逻辑（全部用既有快照字段）；不新开视觉世界——DESIGN.md 的
  The Instrument Panel（灰脊 + 状态色 + One Job Rule + token）不动，本次只换 composition；未触及的
  历史 / 配置视图、顶栏徽章、侧栏、AppShell 保持原样。

## Decision

1. **方向**：实时视图按参考应用版面**分块重做**，旧台账方向作废。同一区域只留一套实现，逐块替换
   （不并行保留两套版面）。
2. **推进顺序**：顶部（页头去重 + 通栏主机条）→ CPU → 内存 → 磁盘 → 网络与时钟；每块一张子票、
   页面在该块完成后保持可用；整页终态在 CPU 块完成后收敛，不提前锁死。
3. **顶部口径（本 ADR 随 #430 落地）**：页头只保留「资源监控 + 实时/历史/配置」；主机信息改为页头下方的
   一条通栏信息条，字段 `主机 / 系统 / 内核 / 已运行`，右端状态槽 `更新于 HH:MM:SS`（跨日带 `MM-DD`），
   停推时同一位置改说 `快照已停 N 秒`；`platform_description` 末尾的 `(kernel …)` / `(build …)` 在展示层剥离、
   内核单列；CPU 型号 · 核数移出主机条（归 CPU 块）；「采样 / 漏拍」不进页头。
4. **参照 pin**：不再走掷骰选方向（impeccable 按 **refinement** 处理，不是新 surface / 新视觉世界）。
5. **旧票处置**：#360 关闭；#373 由 #430 吸收；#374 / #375 / #377 / #378 挂起，台账去留由后续块决定；
   #372 / #376 与版面路线无关，继续有效。

**为什么不用其他方案**：

- **继续台账方向 + 只修 #372–#378**：这些票不改变「台账 vs 分块」的信息架构，解决不了用户指出的「与参照不一致」；
  用户已明确不再要这条路线。
- **重写 DESIGN.md / 换视觉世界**：本次问题在 composition，不在品牌或材质；重写会波及全站 token 消费，
  收益与风险不成比例。
- **一次性整页重写**：分块替换让每一块独立可验收、可回退，避免中间态不可用；也避免再次出现
  「方向拍板后才发现与用户参照不一致」的大返工。

## Consequences

**正面**：版面回到用户参照的「通栏主机条 + 按子系统分块」；主机条行为复用已在插件里验证过的口径
（换行 / 单条不换行 / 双色标签 / 状态槽恒右）；每块独立可验收、可回退；页头从此只有两层，kernel 不再一屏三次。

**负面 / 已知限制**：#360 已合并的台账与页头合并实现会被逐块替换，期间页面处于「新主机条 + 旧台账」的混合态；
#324 的 22 条 UI 评审里与旧版面强相关的结论失效，需按新方向重新判定；本 ADR 与 #360 的历史决策并存，
读者需要知道 0052 已取代其版面结论。

**契约影响**：无（不改帧契约、不改 `generated.ts`；主机条字段全部来自既有快照）。`GLOSSARY.md` 无新术语
（「数据龄」已存在）。
