# ADR 0002: Migrate Build System from xmake to CMake + Conan

## Status

Accepted

## Context

ADR 0001 chose xmake with its built-in package manager for the dztrader project. During development, several issues emerged:

- **Dependency acquisition risk**: xmake's package repository is less comprehensive than Conan Center. Boost and other core dependencies have version/option coverage gaps in xmake repos.
- **Ecosystem alignment**: CMake is the de-facto standard C++ build system with broader IDE/tooling support (clangd, VS, CLion, VSCode all have first-class CMake integration). Conan 2.x is the standard package manager complementing CMake.
- **Best-practice patterns**: Modern CMake (3.28+) with `target_*` commands, `find_package(CONFIG)`, IMPORTED targets, and `CMakePresets.json` is the recommended mainstream approach.
- **Reproducibility**: Conan 2 profiles + `conanfile.py` with pinned versions and explicit options provide reproducible builds across machines.

## Decision

1. **Build System**: CMake 3.28+ with modern target-based syntax
   - `target_include_directories` / `target_link_libraries` / `target_compile_definitions` (no directory-level commands)
   - `find_package(... CONFIG REQUIRED)` with IMPORTED targets from Conan-generated `CMakeDeps`
   - `CMakePresets.json` generated by Conan 2 `CMakeToolchain` (`conan-default` / `conan-release` presets)
   - `gtest_discover_tests` for test registration (not legacy `gtest_add_tests`)

2. **Package Manager**: Conan 2.x
   - `conanfile.py` with `package_type = "application"` and explicit `default_options`
   - Profile `profiles/win-msvc-static` for static CRT (MSVC MT/MTd via `compiler.runtime=static`)
   - Boost 1.90.0 with component-level `without_*` options to minimize build footprint
   - spdlog with `use_std_fmt=True` (matches project's `SPDLOG_USE_STD_FORMAT` macro, no fmt dependency)

3. **MSVC Configuration**:
   - Static CRT via `CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>"`
   - `/utf-8` for UTF-8 source files (avoids C4819/C2065 errors with non-ASCII in comments)
   - `/W4 /permissive-` for strict conformance; `/WX` only in Release
   - `/wd4100` to suppress unreferenced-parameter noise (common in interfaces/callbacks)

4. **Third-party SDKs**: Closed-source CTP API wrapped as CMake IMPORTED target (`dz_ctp_md SHARED IMPORTED`) with `IMPORTED_LOCATION`/`IMPORTED_IMPLIB` and post-build DLL copy.

5. **Version Source**: `project(VERSION 0.0.1)` in root `CMakeLists.txt` is the single source of truth. `configure_file` processes `version.h.in` to generate `version.h`.

## Consequences

- **Build system requires CMake + Conan knowledge** (replaces xmake knowledge requirement from ADR 0001).
- **Standard toolchain**: CMake >= 3.28, Conan 2.x, VS 2022 / GCC 12+.
- **First-time setup** requires `conan install` before `cmake --preset`.
- Boost component options must be kept in sync between `conanfile.py` and actual `find_package` usage.
- Ninja single-config generator: `$<CONFIG>` genex expands to `CMAKE_BUILD_TYPE` at configure time; binaryDir already includes config, so install does not need `--config`.
- Tests use per-file independent compilation pattern with `file(GLOB ... CONFIGURE_DEPENDS)` + `gtest_discover_tests`.

## Migration Scope

All 563 unit tests pass on CMake+Conan. Migrated modules:
- `libs/core`, `libs/log`, `libs/shm`, `libs/strategy_api` (static + shared)
- `apps/dz_master` (dz_master_lib, dz_master, dz_test_worker)
- `apps/gateways/ctp` (dzmd_ctp with CTP IMPORTED target)

`xmake.lua` deleted. `.xmake/` cache directory added to `.gitignore`.
