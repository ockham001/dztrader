# ADR 0019: 策略 SDK 数据库后端范围收敛

## Status

Accepted（2026-10-18）

## Context

- ADR 0015 定了端口-适配器接口，ADR 0016 决定 SQLite + Boost.MySQL **静态内嵌**进策略 SDK
  （单文件分发、无运行时 DB 依赖），Mongo/原版 MySQL 等留给"动态库插件或代理适配器"，
  两者都需另立 ADR。
- 用户诉求：一个 SDK 到处写策略，不想为每种数据库携带一堆 dll/so；同时不希望数据库
  （尤其归档/历史 K 线库）把本版本拖复杂。
- 现状：驱动注册缝已存在但只承载内置驱动；插件形态缺 C ABI 握手，代理形态缺传输协议，
  两者都未实现，也不应在本版本顺手引入。

## Decision

1. **策略可见后端收敛为 `sqlite` + `mysql`**（两者已静态内嵌进 SDK，单文件分发）。
   策略进程内不再支持其他后端。
2. **其他后端不进策略 SDK**：仅平台/归档侧按既有配置使用；策略要读时由对应进程镜像成
   sqlite/mysql（或未来代理）。**动态库插件不做**（C++ ABI/CRT 差异、各平台分发负担，
   与"单 SDK"目标相反）。
3. **代理适配器**（独立服务进程 + 本地 IPC 协议）保留为将来支持任意后端的唯一扩展路径，
   另立 ADR 实现；本版本不设计、不实现。
4. **本版本不新增归档数据库**（bar 存储/查询）；历史 K 线归档域另行 spec。
   `dz_db_query_bar` 保留声明但返回 `DZ_EC_NOT_IMPLEMENTED`，不是可用的查询接口。
5. 现有 SDK 只读 td 库能力（instruments 元数据、ingest 水位/回补）不动——它是合约元数据与
   TD 数据同步语义的地基，不在本轮收敛范围内。

## Alternatives

- **现在就设计/实现代理适配器**：新子系统 + IPC 协议 + 策略可用性依赖，收益为零
  （当前无策略需要 Mongo 等后端）。**后置**。
- **动态库插件**：需要 C ABI（`abi_version`/结构体 size/句柄 destroy）+ 每后端 dll/so，
  与"一个 SDK、不带一堆库"的诉求相反。**否决**。
- **全后端统一走服务进程（含 sqlite）**：给热路径（ingest/元数据查询）引入 IPC 与可用性依赖，
  收益不明。**否决**。
- **一次性内嵌所有驱动**：驱动体积/许可/ABI 不可控（ADR 0016 已论证 Boost.MySQL 之外不可行）。
  **否决**。
- **拆掉现有 SDK DB（连查询 API 都不要）**：合约元数据唯一通路是 `dz_db_query_instruments`
  （ADR 0011），ingest 水位/回补依赖 td 库；拆掉等于回滚两个 Accepted ADR 并作废《帧契约：策略》
  的数据同步承诺。**否决**。

## Consequences

- 策略可见的数据库能力冻结在 sqlite+mysql；归档域若部署在 Mongo 等后端，策略侧必须走镜像或
  等未来代理服务，不能直接查询。
- 非嵌入后端的扩展路径被明确为"代理服务 + 另立 ADR"，不再有人提"编个驱动进 SDK"。
- 本版本不新增数据库后端/归档存储代码；仅新增错误码与 `dz_db_query_bar` 的未实现语义（SDK 公开面收口）。
