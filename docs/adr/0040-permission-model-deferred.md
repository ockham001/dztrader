# ADR 0040: 用户账户/策略权限模型延后，WebUI 权限功能整块下线

## Status

Accepted（2026-10-31，#205 路线 B 决策）

## Context

- WebUI 用户管理里原有一套「账户权限 / 策略权限」：前端选项是原型硬编码（4 个账户、6 个策略），后端把任意 `type/id` upsert 进 `user_permissions` 表；列表恒定 hydrate 成空（“0 个账户/0 个策略”）、新建与撤销都不落库、全仓没有任何授权消费方（登录/路由/行情/交易/WS 都不读权限）。这是“能存、能看（假数）、不能用”的功能。
- 这些权限要对应的真实实体尚不存在：TD/账户链路未实现（#82），策略实体、策略可见性与操作权限归 #6，UI_INPUT 命令权限归 #9；当前系统只有 `dzmd_ctp` 一个行情源与 `stg_demo` 示例策略。
- 平台已有的鉴权是角色级：`role=admin|user` 由服务端 `is_admin`/`ControlGuard` 强执（契约 rest §1）；它与上面的账户/策略粒度权限是两件事，本决策不动它。

## Decision

1. **#205 整块下线账户/策略权限功能**：同一提交删除前端权限 UI、原型常量、`getPermissions`/`updatePermissions` API 与类型，后端 `GET/PUT /api/user/{id}/permissions`、`Repository` 权限方法与 `user_permissions` 表（移除建表 + 既有 DB 幂等迁移 drop），并同步删除契约 rest 的端点行。
2. **权限模型延后，不在 #205 落地**：待真实账户/策略实体与授权消费点可用（#6 策略管理与可见性、#9 命令权限、以及真实账户链路）后，按《帧契约：通用规则》§11.3 先改契约再实现；届时由新 ADR supersede 本决策。
3. **角色级鉴权不变**：admin 端点继续由服务端强执，不以前端显隐作为安全边界。

**为什么不用路线 A（现在就落地权限模型）**：

- 没有可挂靠的真实账户/策略实体，也没有可派生的只读数据源；强行实现只能再造一套原型数据，正是 #205 要清掉的问题，且会把 #6/#9 的边界提前焊死。
- 没有任何授权消费点时，补齐「加载 hydrate + 全量 diff」仍然只是展示数据；要形成安全边界必须同时做 UI 显隐与服务端强执，并先定义权限语义，工作量与依赖都超出本票。

## Consequences

- 正面：清掉“原型常量冒充真实选项”和“能存不能用”的假功能；DB 不再写入无消费方的行；用户管理不再展示恒为 0 的权限列；契约与实现一致。
- 负面：用户管理短期内没有账户/策略粒度权限；若近期确有需求，需先落地实体与授权消费点，不能靠恢复旧实现补齐。
- 迁移：既有 DB 的 `user_permissions` 表被 drop（数据为原型残留、无消费方）；未来重建权限模型时按新契约重新建表。
- 测试责任：前端补“权限 UI 已下线”断言，后端删除对应端点/Repository 用例后其余用户 CRUD 与角色鉴权测试保持全绿。
