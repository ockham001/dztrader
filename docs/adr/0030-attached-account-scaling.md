# ADR 0030: 挂靠账户的缩放、同步与记账口径

## Status

Accepted（2026-10-27 评审通过；2026-10-21 BarStrategy 设计评审）

## Context

- [ADR 0028](0028-strategy-process-logical-account.md) 定了「一个策略进程 = 一个逻辑账户 + 0..N 个按比率挂靠的实体账户」。本 ADR 定执行与记账细节：逻辑持仓怎么来、每笔策略单在各账户下多少手、什么时候发同步单、回放期怎么重建逻辑持仓、上报时机。
- TB 的事实口径：图表虚拟账户由信号推出、与真实账户无关；真实账户按「系统倍数」挂靠，委托手数 = 策略头寸 × 账户倍数；实盘与系统的差异由账户级头寸监控 + 手工一键同步处理，不做自动补差。
- 平台事实：委托 effect 主用 `DZ_POSITION_EFFECT_AUTO`（td 按账户配置解析开平/锁仓，平台专项 issue #82）；成交回报由 SDK 按 `strategy_id` 定向过滤后到达，但框架 v1 不建成交台账、不依赖成交回报（实际与逻辑差异由一键同步处理）。
- 早前版本曾决定「逻辑持仓由成交回报驱动、position_effect 按逻辑持仓推导、不跟踪在途」。在「逻辑账户 + 挂靠比率」模型下，成交反推逻辑持仓在数学上不成立（各账户 scale 之和任意、部分成交/拒单会污染），委托级 effect 推导也不再需要（AUTO 由 td 解析）。本 ADR 取代上述口径。

## Decision

1. **虚拟台账（TB 虚拟账户口径）**：B 的每笔交易意图按传入限价即时记账更新策略虚拟净持仓 `P`（`P` 按 [ADR 0027](0027-bar-strategy-framework.md) 决策 9 的开平规则推进：反向目标化、出口只减不增并钳制、`volume=0` 只平不建/全平），不等待成交、不跟踪在途；Tier 1 统计（均价、建仓次数、浮动盈亏、进出场时间）在同一个下单漏斗里按虚拟成交的开平归属计算。成交回报不回流逻辑持仓。
2. **目标/逻辑持仓**：挂靠账户 `i` 在某品种上的逻辑持仓 `L_i = sign(P) × f(scale_i × |P|)`；`f` 为进程级取整策略（默认四舍五入；可选向少/向多取整；可选「目标非零时至少 1 手」）。
3. **正常策略单**：每账户手数 = `L_i(P_new) − L_i(P_old)`，方向取符号，`position_effect = AUTO`，价格用 B 传入的限价（tick 对齐、涨跌停夹取）。反手/全平同样是一张 AUTO 差量单，由 td 按账户持仓拆平/开（issue #82），框架不推导 effect、不拆单；不看实际持仓、不做差额吸附。
4. **生命周期命令的同步单**：`account add/set/del` 或 `instrument del` 带 `sync` 时，先按命令引起的逻辑持仓变化量发单：`account add` 为 `new_l`（新账户 `old_l = 0`）、`account set scale` 为 `new_l − old_l`、删除账户/品种为 `−old_l`；方向取符号、effect=AUTO，价格默认对手价（买用卖一、卖用买一；tick 对齐、夹涨跌停），命令可选用市价。**下单后无论是否成交（含下单失败）都把逻辑持仓更新为目标值**（删除则移除并清零上报）；不查询实际持仓、不确认成交、不建成交台账；命令本身失败（如写配置失败）则不发单、逻辑不变。已确认口径（2026-10-21）：`account add` 的差额按 `new_l` 计算（假设该账户这些品种实际持仓为 0；若已有仓则 sync 叠加，偏差交给一键同步）；`instrument del` 与账户命令一样支持 `[sync|nosync] [market]`；下单失败（含写帧失败）或未成交也更新逻辑，只有命令层失败才不发单、不变逻辑。
5. **回放期虚拟成交**：进程启动的历史回放中 B 照常运行和下单，订单只做虚拟成交（更新 `P`、Tier 1 与各账户 `L`），不落地、不逐笔上报；全部品种回放完成后一次性上报各账户逻辑持仓。停机期间的真实成交在启动时不可见（SDK ingest 水位过滤），逻辑与实际的差异由操作员一键同步处理。回放深度即恢复范围，持仓周期超出回放窗口时恢复不完整（TB 图表同款限制）。
6. **上报时机**：每次逻辑持仓变化后上报受影响账户的最新 `L_i`（`DZ_FRAME_SET_LOGICAL_POSITION`）；删除账户用「账户 + 空品种」通配清零；策略级 `P` 不单独上报。
7. **净头寸与 AUTO**：系统只按净额记账/对账；账户模式（净头寸/锁单/正常）与开平/今昨拆分由 td 按 AUTO 解析，框架不建模，多空明细失真可接受。`DZ_POSITION_EFFECT_AUTO` 的平台实现是硬前置（issue #82）。
8. **不做的事**：不做「差额吸附」（正常单不吸收不同步差额；差额只由生命周期命令的 sync 或平台一键同步处理）；不做逐单独立取整（会漂移）；不做成交回报台账（框架不跟踪真实成交/委托，实际与逻辑的差异由一键同步处理）；不做框架内一键同步（平台/UI 能力）。
9. **v1 无启动校验**：策略启动后即认为持仓正常；冷启动（归档域未实现）逻辑持仓为 0，是否匹配由操作员负责。

## Alternatives

- **逐单独立缩放**（每笔手数 = `f(scale × 本单量)`）：账户持仓随逐单取整长期漂移（多头累积超配/欠配），与「挂靠比率」语义不符；否决。
- **差额吸附**（正常单把不同步差额吸收进手数）：不同步账户的差额会在下一笔策略单被吸收，可能出现「策略卖、账户买」的反向单；否决。
- **成交反推逻辑持仓**（各账户成交按 scale 折算回 `P`）：比例任意时数学不成立；部分成交/拒单/锁仓会让 `P` 抖动；否决。
- **同步/平仓默认用市价单**：部分交易所/品种不接受市价或吃穿深档；默认对手价（可成交限价），需要最快成交时显式 `market`；否决市价默认。
- **sync 做成独立命令**：命令面只保留在增删改上（用户口径），减少「什么时候该同步」的歧义；单独补差留给未来 WebUI 一键同步；否决。
- **框架内余额/资金/权益参与缩放**：v1 不提供账户资金视图，手数缩放只按比率；将来若需要按资金分配另立 ADR；否决（本版）。

## Consequences

- B 的 `market_position()` / `current_contracts()` 是虚拟台账（下单即更新），与实盘成交、拒单、部分成交无关；TB 迁移用户对此熟悉。
- 挂靠账户的手数序列不保证「每笔策略单 × scale」，保证的是持仓比例（`L` 的差量）；不同步过的账户可能长期偏离，直到一键同步。
- 策略平到 0 时按 `L` 差量发平仓单；不同步/锁仓造成的实际残余由操作员一键同步清理（净额口径）。
- 进程重启（有归档回放时）逻辑持仓自动续上；回放不足或无归档时逻辑持仓为 0，需要操作员处理实盘仓位。
- **同步单的假设**：命令执行前该账户实际仓位 ≈ 旧 `L_i`；框架不建成交台账、也不查询实际持仓，实际已偏时 sync 后仍需账户级一键同步。删除/退出不撤单、不等待成交，残留由操作员处理。
- 性能：每笔交易意图在下单路径多 N 次账户循环与 N 条上报帧（N≈1–3）；tick 热路径不变；回放期不逐笔上报。
- 平台依赖：AUTO 平台专项（issue #82）是实盘联调前置；实现时需新 ADR supersede [ADR 0008](0008-td-position-model.md) 决策 5。
