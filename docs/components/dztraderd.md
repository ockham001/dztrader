# dztraderd（主进程）架构设计

本文档描述 dztraderd 主进程的架构设计与核心机制。

## 进程编排

主进程是全部子进程的唯一编排者：拉起、监控、停止、重启均由主进程集中决策。编排依据为**进程注册表**——主进程启动时从配置加载（拉起依据见「启动顺序」）。

### 启动顺序

- 三趟启动：**第一趟全部行情进程**（同时创建各行情通道元数据，并为每个 md 挂 ready watchdog），**第二趟其余非策略子进程**（交易网关、dzweb 等，立即启动，不等待 md ready），**第三趟同步有界等待被策略引用的 md ready**，逐源启动绑定策略（spawn 前预注册读者 `stg.<name>` 并注入 `DZTRADER_MD_SOURCE`）。
- 等待超时（`master.md_ready_timeout_sec`，默认 5s）后仍未 ready 的源，其绑定策略**不 spawn**，进入 **pending**（状态 `Starting` + message "waiting for md source <name>"），等待晚到 `NOTIFY_MD_STARTED` 补启动。
- md 就绪等待期间：master 同步 drain event channel 处理 `NOTIFY_MD_STARTED`（`start_all` 在 `ioc.run()` 之前执行，不能依赖 asio 异步）。
- 非策略子进程（含数据存储，归内部进程）的拉起由配置决定；策略进程的存在性由配置决定，**是否拉起由行情源就绪状态决定**，策略配置的 `md_source` 必填（校验非空、长度 ≤63、无路径/控制字符），源缺失时策略 pending 而非配置错误。
- **md ready watchdog（契约 4.5）**：每次 spawn md 进程后启动就绪定时器，收到对应 `NOTIFY_MD_STARTED` 时取消；超时按"是否存在运行中绑定策略"区分——存在则判定该次 md 启动失败，terminate 并走 restart policy；不存在则不杀 md、策略保持 pending、记录 ERROR、等待晚到 STARTED。

### 崩溃检测与自动重启

- **检测**：事件驱动——子进程退出回调触发，无轮询。
- **重启**：全部子进程（含策略）统一按各自重启策略（启用开关、最大次数、退避间隔，按进程可配）自动重启；整体关闭期间抑制自动重启。
- **清理时机**：检测到行情进程崩溃立即标记通道 `Stopped`（保留读者列表与元数据句柄，不关闭通道，策略 reader 保持打开）、代发 `NOTIFY_MD_STOPPED`、上报告警，随后再走重启，不做"保留现场等重启"。

### 停止与整体关闭

- 单进程停止：主进程定向发送停止请求，等待退出，超时强制终止。
- 整体关闭：**逆序停止**——策略（含数据存储）→ 交易网关 → 行情进程 → dzweb（UI 最后关闭，可展示关闭进度），与启动顺序严格互逆；逐批停止、等退出、超时强制终止后进入下一批。
- 全部子进程退出（含强制终止收尾）后，主进程自身才退出。
- 广播式全员关闭帧不采用，整体关闭一律走逆序编排。

### 孤儿进程清理与单实例

- 主进程自身崩溃后残留的子进程（孤儿），由主进程**下次启动时一次性扫描并终止**（依据持久化的子进程 PID 记录）；运行期不做心跳探测。
- 主进程崩溃到重启的空窗期内，子进程对 event 通道的写入照常；残留数据由下次启动的孤儿清理与通道重建流程处置。
- 主进程以**文件锁**保证全系统单实例运行。

### 动态注册

对未注册进程的 Start 请求，主进程找到同名网关可执行文件即动态注册（写配置持久化）并启动；策略进程有独立注册流程，不适用。进程存在性以配置为唯一真相源。

## 并发与调度

**无轮询**：一切事件源均由信号量或回调驱动，绝不采用轮询。

### 线程模型

**asio 主线程**（io_context 单线程）：承载全部逻辑。

**信号量监听线程**（唯一额外线程）：阻塞等待 event 通道信号量，被唤醒后仅向主线程投递「排空通道」任务，随即继续等待；自身不读取、不解析、不处理任何数据。

## SHM 通道

主进程统一管理全部通道的元数据与订阅者（读者）列表。

### event 通道：宿主与权威写者

- **meta 单一实例共享**：reader / writer / cleaner 持有同一 meta 实例；进程内读写均在主线程、零同步，跨进程由 meta 内建机制保证。
- **锁模型**：writer 持有 1 个崩溃安全的进程锁（跨进程写互斥）；reader 无锁；无任何线程锁。
- **权威写者职责**：主进程经 event 通道写进程状态、订阅者变更、生命周期通知等系统帧，是系统权威信息的源头。
- **信号量分配**：每进程一个命名信号量，由主进程创建并按进程身份分配；通道写入后按读者列表唤醒目标进程信号量。

### 进程身份（instance_id）

- 每进程一个、全局唯一：二进制 C++ 程序为可执行文件名；Python 程序为 .py 入口文件名。
- 非策略进程直接以进程名标识，不加前缀。
- 策略进程加前缀 `stg.`，加前缀后全局唯一。

### 订阅者管理

- 事件通道订阅者由**主进程统一维护**：拉起子进程即注册、停止即注销（主进程自身也在启动时注册）。
- 每次变更通过事件通道广播更新帧，通知所有进程刷新本地订阅者缓存。
- 订阅者以进程身份命名，重启复用同名。

### 页文件生命周期与旧页清理

- 页文件前向追加、序号只增不减；旧页由清理机制删除，防止磁盘无限增长。
- **主进程是唯一清理者**：统一清理 event 与全部行情通道——删除下限需全量读者视图，只有统一维护读者列表的主进程具备全局判断能力。
- **删除下限**：仅删除低于所有读者 / 写者最小页序号的页，消费者在用页绝不删除。
- 清理策略（保留页数 + 保留时长）全局统一一份挂主进程，皆为 0 表示不清理；随主进程维护定时器周期执行，无独立线程。

### 行情通道：读者（接入）规则

行情通道的读者（接入）规则，区别于订阅合约规则。术语约定：本节"订阅"仅指订阅合约；打开 / 关闭行情通道称为"接入 / 断开接入"（成为 / 退出读者）。

#### 谁可接入

任何进程均可接入行情通道，不限策略。

#### 接入与断开

- **接入**：进程必须先向主进程发送接入该通道的请求，收到响应之后才能接入；否则接入的通道不保证安全，且不会有信号量唤醒（主进程未将该进程加入读者列表）。初始接入由进程自行发起请求，不依赖 `NOTIFY_MD_STARTED`；该广播仅用于重接入。
- **接入失败**：运行期间（主进程启动流程完成之后）若请求的通道对应的行情进程未配置（主进程不会拉起）、未运行，或通道未就绪（行情进程尚未发出 `NOTIFY_MD_STARTED`），响应携带失败信息，接入进程不得接入该通道。接入请求在途时行情进程停止的，同样按接入失败处理。失败后的后续处理（重试、放弃）由接入进程自行负责，本规则不作约定。已 tombstone（被 Remove）的通道同样按"未配置"拒绝接入。
- **主动断开**：行情进程运行期间，接入进程可向主进程发送断开请求，由主进程将其从读者列表移除。
- **强制清理**：接入进程退出或崩溃时，由主进程代为清理其读者记录，防止僵尸读者。本条清理接入进程自身的读者记录，与下述行情进程停止时保留整表的处理相互独立、互不覆盖。

#### 启动顺序

主进程启动时优先启动行情进程，通道由主进程创建，确保通道先于接入者存在（编排细节见「进程编排」）。策略进程不再自行发起接入（1013），而由主进程在 spawn 前统一预注册读者（`stg.<name>`）。

#### 行情进程生命周期

- **`NOTIFY_MD_STARTED`（行情进程发送）**：行情进程在通道就绪、可接受合约订阅时即发送，不以完成登录为前提——未登录状态下其他进程同样可订阅合约，仅暂不转发至柜台。策略进程收到后由 SDK `dz_on_md_started` 按期望集合全量补订阅（不重开 reader、不重新接入）。普通策略的读者生命周期与进程同长，md 停止/删除时不关闭。
- **`NOTIFY_MD_STOPPED`（主进程发送）**：此前接入过该通道的进程收到后，此前订阅的合约无效；继续订阅虽无效但不导致崩溃（容错设计），建议不订阅。普通策略模板忽略该帧（reader 保持打开，`dz_on_md_started` 重启后自动恢复订阅）。
- **停止后果**：行情进程停止时（正常停止或崩溃），通道标记 `Stopped`，**保留读者列表与元数据句柄**（策略 reader 与进程同生命周期，PageCleaner 仍需遍历该通道以保护存活 reader）；通道本身不销毁。
- **移除后果**：移除行情源（Remove，配置已删）时，主进程将通道标记 **tombstone**——**不删文件、不清空读者列表、不释放元数据句柄**，仅供 PageCleaner 继续清理旧页与同源重加复用；此后接入请求按"通道未配置"失败。与停止后果的"保留待重启复用"不同，tombstone 的配置已删，同源重新添加时走 page_size 复用/重置逻辑。物理清理（`destroy_md_channel`，删除通道目录）仅保留给未来主动维护入口，Remove 流程不再调用。
- **通道关闭条件**：行情进程未运行且无进程接入（读者列表为空）时，主进程必须标记该通道 `Stopped` 并复位就绪标志；不触碰数据文件、读取位置、page_size 与读者列表（保留待重启复用），停止期间旧页清理按现有规则继续（tombstone 通道也在 PageCleaner 遍历范围内）。
- **崩溃重启过程的边界**：自主进程检测到行情进程崩溃（发出 `NOTIFY_MD_STOPPED`）开始，至以下任一时刻结束——重启成功（新行情进程发出 `NOTIFY_MD_STARTED`），或主进程放弃重启（重启策略禁用、超过最大重试次数、重启拉起失败、收到移除请求）。放弃重启后，该行情进程视为"未运行"。

#### page_size 可改性

page_size 可改的充要条件：无运行中绑定策略（读者列表中的策略 reader 均已释放或策略已退出），且行情进程未运行（非正常运行中、非崩溃重启过程中）。凡不满足者均不可改：行情进程正常运行中，或有运行中绑定策略（其 reader 仍映射旧 page_size 页文件）。

page_size 仅人工经配置文件修改（SET 帧完全跳过该字段，无程序化修改入口）。master 在 `MdChannelState` 保存每个通道最近一次 page_size；md 启动时若配置 page_size 与 `last_page_size` 不一致且无运行中绑定策略，则释放旧 meta 后重新 `open_or_create`，由通道内建机制重置：自动清空全部页文件、写位置归零、按新值重建。tombstone 复用场景的 page_size 比较必须使用 `last_page_size`，不能只重读 `<source>.json`（Remove 后文件缺失，默认值会误判为变更并触发意外重置）。

## 设计原则

- **主进程集中编排**：拉起、监控、停止、重启全部由主进程统一决策；子进程不互相编排，进程存在性以配置为唯一真相源。
- **事件驱动、无轮询**：子进程退出由异步回调感知，通道唤醒由信号量驱动，运行期不做心跳探测。
- **状态变化即持久化**：运行中策略清单等关键状态在变化时落盘，主进程任意方式重启（含崩溃）后均可准确恢复。
- **清理先于恢复**：检测到异常立即清理现场（读者列表清空、关闭通道、代发通知），恢复（重启、重新接入）基于干净状态重建，不携带旧状态衔接。
- **异常自愈并记录告警**：子进程崩溃由重启策略自动恢复，非本进程原因的异常同时记录日志、上报告警，供排查而非静默或阻塞。
