# dztraderd（主进程）架构设计

本文档描述 dztraderd 主进程的架构设计与核心机制。

## 进程编排

主进程是全部子进程的唯一编排者：拉起、监控、停止、重启均由主进程集中决策。编排依据为**进程注册表**——主进程启动时从配置加载（拉起依据见「启动顺序」）。

### 启动顺序

- 两趟启动：**第一趟全部行情进程**（同时创建各行情通道元数据），**第二趟其余全部子进程**（交易网关、dzweb、数据存储、策略进程）。
- 各批次间**不等待就绪**：初始接入走请求-响应（见「行情通道：读者（接入）规则」），不依赖 `NOTIFY_MD_STARTED` 广播。
- 非策略子进程（含数据存储，归内部进程）的拉起由配置决定；策略进程的存在性由配置决定，**是否拉起由上次运行中清单决定**，清单在策略启动 / 停止时**状态变化即持久化**，主进程崩溃重启后依然准确。

### 崩溃检测与自动重启

- **检测**：事件驱动——子进程退出回调触发，无轮询。
- **重启**：全部子进程（含策略）统一按各自重启策略（启用开关、最大次数、退避间隔，按进程可配）自动重启；整体关闭期间抑制自动重启。
- **清理时机**：检测到行情进程崩溃立即清理（清空读者列表、关闭通道、代发 `NOTIFY_MD_STOPPED`、上报告警），随后再走重启，不做"保留现场等重启"。

### 停止与整体关闭

- 单进程停止：主进程定向发送停止请求，等待退出，超时强制终止。
- 整体关闭：**逆序停止**——策略 → 数据存储 → 交易网关 → 行情进程 → dzweb（UI 最后关闭，可展示关闭进度），与启动顺序严格互逆；逐批停止、等退出、超时强制终止后进入下一批。
- 全部子进程退出（含强制终止收尾）后，主进程自身才退出。
- 广播式全员关闭帧不采用，整体关闭一律走逆序编排。

### 孤儿进程清理与单实例

- 主进程自身崩溃后残留的子进程（孤儿），由主进程**下次启动时一次性扫描并终止**（依据持久化的子进程 PID 记录）；运行期不做心跳探测。
- 主进程崩溃到重启的空窗期内，子进程对 event 通道的写入照常；残留数据由下次启动的孤儿清理与通道重建流程处置。
- 主进程以**文件锁**保证全系统单实例运行。

### 动态注册

对未注册进程的 Start 请求，主进程找到同名网关可执行文件即动态注册（写配置持久化）并启动；策略进程有独立注册流程，不适用。进程存在性以配置为唯一真相源。

## 并发与调度

**无轮询**：一切事件源均由信号量或回调驱动，绝不采用轮询。

### 线程模型

**asio 主线程**（io_context 单线程）：承载全部逻辑。

**信号量监听线程**（唯一额外线程）：阻塞等待 event 通道信号量，被唤醒后仅向主线程投递「排空通道」任务，随即继续等待；自身不读取、不解析、不处理任何数据。

## SHM 通道

主进程统一管理全部通道的元数据与订阅者（读者）列表。

### event 通道：宿主与权威写者

- **meta 单一实例共享**：reader / writer / cleaner 持有同一 meta 实例；进程内读写均在主线程、零同步，跨进程由 meta 内建机制保证。
- **锁模型**：writer 持有 1 个崩溃安全的进程锁（跨进程写互斥）；reader 无锁；无任何线程锁。
- **权威写者职责**：主进程经 event 通道写进程状态、订阅者变更、生命周期通知等系统帧，是系统权威信息的源头。
- **信号量分配**：每进程一个命名信号量，由主进程创建并按进程身份分配；通道写入后按读者列表唤醒目标进程信号量。

### 进程身份（instance_id）

- 每进程一个、全局唯一：二进制 C++ 程序为可执行文件名；Python 程序为 .py 入口文件名。
- 非策略进程直接以进程名标识，不加前缀。
- 策略进程加前缀 `stg.`，加前缀后全局唯一。

### 订阅者管理

- 事件通道订阅者由**主进程统一维护**：拉起子进程即注册、停止即注销（主进程自身也在启动时注册）。
- 每次变更通过事件通道广播更新帧，通知所有进程刷新本地订阅者缓存。
- 订阅者以进程身份命名，重启复用同名。

### 页文件生命周期与旧页清理

- 页文件前向追加、序号只增不减；旧页由清理机制删除，防止磁盘无限增长。
- **主进程是唯一清理者**：统一清理 event 与全部行情通道——删除下限需全量读者视图，只有统一维护读者列表的主进程具备全局判断能力。
- **删除下限**：仅删除低于所有读者 / 写者最小页序号的页，消费者在用页绝不删除。
- 清理策略（保留页数 + 保留时长）全局统一一份挂主进程，皆为 0 表示不清理；随主进程维护定时器周期执行，无独立线程。

### 行情通道：读者（接入）规则

行情通道的读者（接入）规则，区别于订阅合约规则。术语约定：本节"订阅"仅指订阅合约；打开 / 关闭行情通道称为"接入 / 断开接入"（成为 / 退出读者）。

#### 谁可接入

任何进程均可接入行情通道，不限策略。

#### 接入与断开

- **接入**：进程必须先向主进程发送接入该通道的请求，收到响应之后才能接入；否则接入的通道不保证安全，且不会有信号量唤醒（主进程未将该进程加入读者列表）。初始接入由进程自行发起请求，不依赖 `NOTIFY_MD_STARTED`；该广播仅用于重接入。
- **接入失败**：运行期间（主进程启动流程完成之后）若请求的通道对应的行情进程未配置（主进程不会拉起）、未运行，或通道未就绪（行情进程尚未发出 `NOTIFY_MD_STARTED`），响应携带失败信息，接入进程不得接入该通道。接入请求在途时行情进程停止的，同样按接入失败处理。失败后的后续处理（重试、放弃）由接入进程自行负责，本规则不作约定。
- **主动断开**：行情进程运行期间，接入进程可向主进程发送断开请求，由主进程将其从读者列表移除。
- **强制清理**：接入进程退出或崩溃时，由主进程代为清理其读者记录，防止僵尸读者。本条清理接入进程自身的读者记录，与下述行情进程停止时清空整表的清理相互独立、互不覆盖。

#### 启动顺序

主进程启动时优先启动行情进程，通道由主进程创建，确保通道先于接入者存在（编排细节见「进程编排」）。

#### 行情进程生命周期

- **`NOTIFY_MD_STARTED`（行情进程发送）**：行情进程在通道就绪、可接受合约订阅时即发送，不以完成登录为前提——未登录状态下其他进程同样可订阅合约，仅暂不转发至柜台。此前接入过该通道的进程收到后应重新接入该通道（走「接入与断开」流程）并重新订阅合约。
- **`NOTIFY_MD_STOPPED`（主进程发送）**：此前接入过该通道的进程收到后，此前订阅的合约无效；继续订阅虽无效但不导致崩溃（容错设计），建议不订阅。
- **停止后果**：行情进程停止时（正常停止或崩溃），读者列表清空、通道关闭、接入关系自动解除、旧句柄失效，统一由主进程执行（与 `NOTIFY_MD_STOPPED` 由主进程代发同理）；通道本身不销毁。
- **移除后果**：移除行情源（Remove，配置已删）时，主进程在停止后果之上**彻底销毁通道**——清空读者列表、删除通道目录（meta 与全部页文件）、删除通道条目，此后接入请求按"通道未配置"失败。与停止后果的"保留待重启复用"相对；移除后同源重新添加时按新配置全新创建。删除失败仅记录告警不中断（文件可能仍被其他进程映射，延迟释放）；残留文件待同源重新添加时兜底——page_size 与遗留不一致则重建时自动重置（清空页文件），一致则复用遗留数据续写、旧页由周期清理机制消化。
- **通道关闭条件**：行情进程未运行且无进程接入（读者列表为空）时，主进程必须关闭该通道并清空读者列表；关闭不触碰数据文件、读取位置与 page_size（保留待重启复用），停止期间旧页清理暂停（无写入者无新页），通道重开后恢复清理。
- **崩溃重启过程的边界**：自主进程检测到行情进程崩溃（发出 `NOTIFY_MD_STOPPED`）开始，至以下任一时刻结束——重启成功（新行情进程发出 `NOTIFY_MD_STARTED`），或主进程放弃重启（重启策略禁用、超过最大重试次数、重启拉起失败、收到移除请求）。放弃重启后，该行情进程视为"未运行"。

#### page_size 可改性

page_size 可改的充要条件：行情进程未运行（非正常运行中、非崩溃重启过程中），且读者列表为空（含已退出进程的记录均已被主进程清理）。凡不满足者均不可改：行情进程正常运行中、崩溃重启过程中（无论是否有读者），或读者列表非空。

page_size 仅人工经配置文件修改（SET 帧完全跳过该字段，无程序化修改入口）。变更由通道内建机制自动重置：元数据重建时发现配置值与现存不一致，自动清空全部页文件、写位置归零、按新值重建；该行为是上述可改性条件的底层支撑，读者列表为空的要求保证重置时无消费者受损。配置修改在通道关闭期间持久化、于下次行情进程启动时经自动重置生效。

## 设计原则

- **主进程集中编排**：拉起、监控、停止、重启全部由主进程统一决策；子进程不互相编排，进程存在性以配置为唯一真相源。
- **事件驱动、无轮询**：子进程退出由异步回调感知，通道唤醒由信号量驱动，运行期不做心跳探测。
- **状态变化即持久化**：运行中策略清单等关键状态在变化时落盘，主进程任意方式重启（含崩溃）后均可准确恢复。
- **清理先于恢复**：检测到异常立即清理现场（读者列表清空、关闭通道、代发通知），恢复（重启、重新接入）基于干净状态重建，不携带旧状态衔接。
- **异常自愈并记录告警**：子进程崩溃由重启策略自动恢复，非本进程原因的异常同时记录日志、上报告警，供排查而非静默或阻塞。
