# dzmd_ctp 架构设计

本文档描述 dzmd_ctp 行情进程的架构设计与核心机制。

## 并发与调度

### 线程划分

**CTP SPI 回调线程**（CTP SDK 内部）

- 行情回调 `OnRtnDepthMarketData` → 直接写共享内存
- 非行情回调 → 打包入队列，转发给主线程

**主线程**

- 处理 SPI 线程转发的非行情事件
- 处理 event 通道帧
- 驱动定时任务

### 命名信号量

进程内只创建了一个命名信号量，SPI 事件队列和 event 通道共用它，主线程靠这一个信号量唤醒即可同时响应两类事件源；定时调度也复用它的超时等待，无需独立机制。

### 定时调度机制

- 定时器队列是**定时调度的核心宿主**，承载全部延时 / 周期任务（固定时间点、固定时间间隔）。
- 它**无需外部额外线程**即能按点唤醒，关键在于**复用主循环信号量的超时等待**。
- 定时精度要求 100ms 级别，按此精度设计，无需独立线程。
- 无到期定时器时不设超时，仅由事件唤醒，CPU 接近零。
- 所有定时任务共享**同一宿主机制**，不为其各自开辟独立线程或单独轮询。

## SHM 通道

### 行情通道：单写者模型

- 进程内唯一写入点为 SPI 线程的 `OnRtnDepthMarketData`。
- 进程不读取行情通道的行情数据。
- SPI 线程无法被主动唤醒，页面预加载、旧页回收（解除旧页内存映射；页文件删除由主进程统一执行）等维护操作由主线程执行；这些维护为**主动定时触发**，由主线程自行驱动。
- 读取端列表刷新为**被动响应**：收到主进程广播的 `UPDATE_SHM_MD_SUBSCRIBER` 帧后刷新（见《帧契约：SHM 通道配置》），无轮询。
- SPI 线程写入与主线程维护由自旋锁互斥，保护范围仅限行情通道。
- **生命周期宣告**：本进程在通道就绪、可接受合约订阅时广播 `NOTIFY_MD_STARTED`，不以完成登录为前提（未登录同样接受订阅，暂不转发柜台）；停止时不自宣（崩溃时无法自宣），由主进程代发 `NOTIFY_MD_STOPPED`。

### event 通道：多写者模型

- 写入端由**进程锁（崩溃安全）**保护跨进程写入互斥。
- 进程内 event 通道的读取与写入均由主线程独占。
- 读取端无需锁：主线程独占读取，读取端不持有跨线程锁。
- 跨进程读写安全由通道内建发布机制保证：帧完整写入后才原子发布写位置，读取只消费已发布的帧，无需参与写锁。
- event 通道的维护为**被动响应**：按收到的对应帧做相应处理，无独立的定时维护，均由到达帧被动触发。

## 会话与订阅

### 登录会话模型

- 本进程不发起登出请求：UI 登出即彻底释放 CTP SDK API（直接断开），回 Idle；不存在"已登出、连接保留"的稳定状态。
- "前置已连接、未登录"仅是登录流程中的瞬态，正常情况下立即自动发起登录。
- 例外：若收到服务器主动登出的回调，状态已偏离预期，属异常情况，非本进程主动为之。此时保留前置连接，由自动调度重新登录恢复，并记录错误日志、上报告警，供排查。

### 订阅合约

订阅按"**合约 + 订阅者列表**"维护：每个合约记录其订阅者集合（策略 / 进程）与订阅状态。

- 此**订阅者指订阅该合约的策略 / 进程**，区别于行情通道的读取端列表（后者是 SHM 读者，由 `UPDATE_SHM_MD_SUBSCRIBER` 广播被动刷新维护，见「SHM 通道」）。
- **乐观退订**：发送退订即置未订阅状态，不等 CTP 回调反馈；遵循"宁多勿少"原则——宁可多订 / 多收，也不漏订。

## 设计原则

- **锁选型对齐并发模型**：单写者用轻量自旋锁（进程内跨线程互斥）；多写者用崩溃安全的进程锁（跨进程互斥）；读取端无锁。锁不跨出通道边界。
- **实时写入优先于后台维护**：两者竞争时，实时写入优先，后台维护不得长时间占用。
- **主动与被动职责分明**：维护要么由定时器主动触发、要么按到达帧被动响应，由主线程集中承载，不混淆。
- **宁多勿少，容错优先**：具不确定性的操作（如退订）采用乐观策略，宁可多发 / 多收也不漏，正确性优先于资源精确。
- **异常自愈并记录告警**：非本进程原因的异常，由自动调度恢复，同时记录日志、上报告警，供排查而非静默或阻塞。
- **无轮询**：一切事件源均由信号量或回调驱动，绝不采用轮询。
- **事件驱动、单一宿主**：全部延时调度由统一宿主承载，复用信号量超时唤醒，无多余线程。
